# @internal/plugin-servicelog

The Backstage frontend plugin for ServiceLog (STORY 2.3). Wraps the
host-neutral `@servicelog/core` product (STORY 2.1/2.2) in a real Backstage
new-frontend-system plugin -- Backstage supplies the chrome around it; this
package supplies ServiceLog content only.

## What's here

- `src/plugin.tsx` -- `createFrontendPlugin`, one `PageBlueprint` page at
  `/servicelog`, and an `ApiBlueprint` for the data-fetching API.
- `src/api.ts` -- `ServiceDataSource` (the frontend half of checkpoint D's
  data seam) and its real implementation, calling the `servicelog` backend
  plugin via `discoveryApi`/`fetchApi`.
- `src/components/ServiceLogPage.tsx` -- the async loading/error wrapper
  around `ServiceLogFeature`, and the `.servicelog-scope` wrapper the
  scoped stylesheet targets.
- `src/styles/servicelog-plugin.css` -- the Tailwind build entry for
  checkpoint B1's plugin-safe styling strategy (no preflight; a scoped
  reset instead). Compiled by `scripts/build-css.mjs` into
  `src/styles/generated/servicelog-css.ts` (gitignored, regenerated by
  `prestart`/`prebuild`) -- a TS string module, not a `.css` file, because
  `backstage-cli package build`'s bundler for this role has no CSS loader.
- `dev/index.tsx` -- the isolated plugin dev harness
  (`@backstage/frontend-dev-utils`'s `createDevApp`); `npm start` here
  hot-reloads just this plugin, no `packages/app`/`packages/backend`
  required.

See `docs/backstage-compatibility.md` for the full compatibility record,
including the real styling-containment bug this package's reset was built
to fix.

## Scripts

- `npm run build:css` -- compile the scoped stylesheet (also runs
  automatically before `start`/`build`).
- `npm start` -- isolated dev harness.
- `npm run build` -- real `backstage-cli package build` output to `dist/`.
